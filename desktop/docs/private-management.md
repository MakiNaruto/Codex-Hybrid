# Intel 桌面私有控制协议

窗口通过固定 Tauri 命令连接打包 Python 的 `desktop-controller` 常驻进程，一次启动、逐条 stdin/stdout JSON 请求响应，不开放管理 HTTP 端口，不接受任意程序或 shell 参数；CC Switch 数据库路径仅通过现有来源切换业务校验和读取。API Key 只经 stdin 传递，不放在命令行或日志；请求上限 64 KiB，错误不回传异常原文和上游正文。Rust 用互斥锁串行配对响应，断连后不自动重试写入。

默认目录为 `~/.codex-hybrid`，Codex 配置为 `~/.codex`，不应用 CLI 的目录环境变量覆盖。尚未初始化时读取状态不创建数据目录；发现已有 settings 或用户主动初始化后才持有服务目录锁。常驻进程复用 ManagementContext、Management 和 ForwardingRuntime，保留同一份预览签名密钥。单次 `desktop-manage` / `desktop-snapshot` 仍作为独立回归入口保留，桌面窗口已不使用它们启动每次操作。

## 共用网页适配

Tauri 加载 `src/management/web/`。浏览器继续使用 `/manage/api/`；桌面将相同路径、GET/POST 和 JSON 请求体发送为 `{action: "web_api", path, method, body}`。控制进程先检查路径、方法和字段白名单，再调用已有 Management 业务；不支持任意 URL、方法、后台函数或 `forwarding/ensure`。接入提交仍复用同会话预览校验；来源、厂商和模型保存使旧预览失效。新增页面使用固定业务错误码与安全网络错误分类，不回传异常原文。请求仍受现有 64 KiB 限制，stdio 串行处理，不自动重放操作。

首次 `state` 返回 `configured: false`，界面提供显式初始化按钮；初始化前不请求诊断。桌面页面不使用网页访问 token。初始化、托盘切换、重启确认和安全退出控件只在桌面显示。旧 `desktop/stage0/web/` 是保留的探针，不再是 Tauri 前端入口。

## 固定操作

- `snapshot` / `status`：读取脱敏配置、接入状态、网关状态及活动；不启动转发。已有配置启动会建立管理对象与锁，并沿用完成事务记录清理，不是零文件操作。
- `initialize`：用户点击后读取官方配置和缓存，准备管理配置和恢复基线；不改写 Codex 文件、不启用接入、不监听模型端口。已有 settings/state 拒绝覆盖，新配置要求管理鉴权。
- `save_provider`：复用现有保存业务，要求 revision，保留未编辑高级参数和留空 Key；Key 不回显，CC Switch 只读。保存会发布目录，但不自动发送测试或切换接入。
- `test_connection`：用户点击后测试已保存模型；复用现有适配、macOS 代理规则和 60 秒上游超时，可能消耗 API 额度。只返回完成状态及耗时。
- `preview_routing`：提交 project/openai，预检并刷新模型目录，返回签名版本、会话/模型/索引影响数量、活动和客户端检测摘要；此时不改写 Codex 配置或迁移索引。
- `cancel_preview`：丢弃待确认版本；不会回滚预览期间已刷新的本地模型目录。
- `save_desktop_preferences`：分别记住开启/关闭的 ask、auto、never。偏好保存不触发桌面操作。
- `set_routing`：必须匹配同一控制会话内的待确认预览，携带明确活动确认和可选桌面操作。复用现有 HMAC/版本复核、配置及索引事务；开启先确认网关健康，再写配置。取消、过期版本或网关启动失败不能启用接入。配置结果与 Codex 操作结果分别反馈，不宣称客户端已加载。自动操作沿用平台模块，只尝试一次正常退出/启动，不强杀。
- `recover_forwarding`：只在配置仍为 project 时由用户显式触发，不改写配置。启动后再检查配置，外部修改不会被覆盖。
- `preview_restart` / `cancel_restart` / `restart_codex`：仅 macOS。独立重启不切换配置或启停网关；预览返回活动摘要和两分钟有效的同会话单次票据。确认必须携带 `ticket` 与 `confirm_activity: true`，复核安装及 PID/创建时间；未运行、检测未知、身份变化、已取消或过期时不能执行。正常退出失败不启动、不强杀；启动未确认单独反馈，不重试。接入仍开启但网关未运行时拒绝重启。重启预览和接入预览互相作废；保存或切换配置也使重启票据作废。
- `shutdown`：仅由 Rust 的“退出应用”入口使用。配置仍接入时拒绝；已恢复原生但网关仍有活动、相关 Codex 进程或无法确认安全时保留服务并拒绝退出。没有取得服务所有权的窗口可以退出。成功检查后关闭进程、释放锁并退出应用。

## 生命周期与恢复

2026-11-01 更新：macOS 支持通过后台适配器复用已确认归属的同目录网页服务，前端继续使用私有 IPC；退出仅断开连接，不停止该外部服务。Cmd+Q 已改由原生层直接发起退出，不再依赖页面加载完成；自管接入仍保留恢复确认。首次读取失败显示错误及重试提示。打包布局、超时与平台边界见 [首次加载与退出修复](web-desktop-alignment.md#macos-首次加载与退出修复)，下文早期 Cmd+Q 依赖页面及草稿拦截的描述按历史行为阅读。

启动不自动恢复残留接入或启动网关，用户可以“恢复接入服务”，或预览并确认关闭接入。网关进程沿用现有监督：1、3、10 秒最多重试三次，稳定运行 60 秒重置额度；启动失败不自动重试。关闭接入后若不能确认安全停服，保留网关并提示；之后点击退出会再次检查安全性。

macOS 开发预览已接入 CH 托盘（接入/网关状态、打开窗口、开启或关闭接入、重启 Codex、退出）：关闭按钮隐藏窗口并保留草稿和控制会话；Dock 重开可显示窗口。托盘接入操作重新读取状态并直接打开现有预览确认区，不直接写配置。托盘和窗口共用重启确认区；草稿、切换预览和重启预览互斥。原生层每五秒尝试读取同一控制会话的状态，长请求期间跳过轮询，窗口隐藏不依赖页面计时器；断连显示状态不可用，不自动重启控制会话。安全退出期间暂停轮询，防止退出过程中创建新会话。Cmd+Q、托盘退出与窗口退出按钮共用安全检查，草稿或切换预览未处理时保留窗口；macOS 接入开启时退出会进入现有恢复预览，确认后恢复原生配置并另行请求安全退出；取消不会切换配置，无法确认停服安全时保留应用。macOS 默认 Quit 已替换为自定义 Cmd+Q 菜单命令，避免底层原生 terminate 动作绕过检查。此变化限 macOS，Windows 保留原有关闭拦截行为。

控制程序被意外结束或 stdin EOF 时，关闭其拥有的网关子进程，保留磁盘上的接入配置与恢复基线，下一次启动要求用户明确选择恢复；不会在异常断连时偷偷改写 Codex 配置。正在使用的请求可能因崩溃中断，不能将这条崩溃清理路径称为安全退出。真实 Codex 启停与异常退出后的用户恢复体验仍需专门实机验收。

源码及冻结集成测试仅使用临时 HOME、虚构配置、随机回环端口和健康检查；不会向供应商发送推理请求，不关闭当前 Codex。Windows 与 Apple Silicon 保留后续独立验收。


### macOS 托盘原生确认（2026-11-01）

菜单调整为“管理”、带勾选的“混合路由”、“重启 Codex…”和“退出…”，按窗口入口、日常操作、退出分组。移除常驻状态行，详细状态保留在托盘 tooltip 与管理页；勾选只表示配置已接入，不代表网关健康。状态尚未读取或不可用时禁用切换，避免把未知状态当成关闭。

macOS 托盘事件携带 `native_confirmation` 标志，共享页面只对这些事件使用 AppKit `NSAlert`；网页及其他平台原有确认流程不变。混合路由先调用已有私有预览，再由系统弹窗提供取消、仅切换、切换并重启（未运行时开启可启动）三个选项；“从不自动操作”偏好不提供自动操作按钮。取消清除预览，不切换配置。确认后复用 `set_routing`，保留版本、票据、进程与活动检查；确认超时后仍须重新预览。

“重启 Codex…”使用已有 `preview_restart` / `restart_codex` 功能，系统弹窗明确全窗口影响与活动请求，确认才提交单次票据；取消调用 `cancel_restart`。检测中显示提示，未运行、未知状态、草稿阻挡及服务异常给出可见反馈。原生弹窗在主线程显示，控制请求异步执行；只新增 macOS AppKit 依赖。此轮不改变 Windows 生命周期或任何平台代理规则。

### macOS 复用网页服务时的托盘操作（2026-11-01）

托盘原生确认的接入预览与提交统一走 `web_api` 的 `routing/preview` 和 `routing`，与窗口开关一致，避免复用网页服务时直接控制命令返回 `SERVICE_ALREADY_RUNNING`。取消不提交配置。

独立重启保留在 macOS 桌面控制器中；复用网页服务时从该服务读取活动摘要，并在预览和确认时重新读取路由及网关状态。网关不可用或服务断连时不重启；单次票据、过期、PID/创建时间复核及正常退出失败不启动的约定不变。经桌面提交的共享管理写入会作废本地重启票据。退出桌面不停止原网页服务，Windows 单实例和重启边界保持原样。
