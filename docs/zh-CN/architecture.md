# 工作原理

[返回首页](../../README.zh-CN.md) · [文档导航](README.md)

```text
Codex：用户目录 config.toml + 所选数据目录 models.json
                         ↓
              本地网关（127.0.0.1:18891）
                 ├─ 官方模型 → OpenAI 官方订阅端点
                 └─ 第三方模型 → 所选供应商 API
                                      ↑
                             YAML / CC Switch 只读来源
```

Codex 从自身的 `config.toml` 读取网关地址及模型目录路径；本地网关读取数据目录中的
`settings.json`，再加载当前 YAML 或 CC Switch 来源。主 agent 与子 agent 共用原生模型目录，
按模型 key 路由，不经过 MCP。

官方请求也经过本地网关。官方订阅认证仅发送给固定官方端点，第三方请求使用对应供应商 Key。
配置、凭据、令牌和备份保存在所选数据目录；含凭据文件不要提交版本控制。
生成文件使用 POSIX `0600` 权限，Windows 依赖目录 ACL。

### 协议兼容边界

第三方 Responses 与 Chat Completions 共用历史规范化：保留对话正文、工具调用及其结果；可读的历史推理或摘要作为普通历史文本传递，不跨端点转发加密推理。外部请求中的 system/developer 消息按原顺序汇总到系统指令区，Responses 使用顶层 `instructions`，Chat 使用唯一的首条 system 消息。官方路由保留原生加密历史，不应用这项外部降级。

系统指令归并只处理消息，不把带 developer 角色的工具元数据当成文本。桌面端可能以没有 `call_id` 的具名工具输出封装任务通知；它们作为保留来源的普通上下文传递，不伪造工具调用。真正带调用 ID 的工具结果保持原有配对。

两个协议共用 SSE 分帧，支持多行数据及仅在 `event:` 中声明的事件类型。显式上游错误转换为脱敏的失败终态；协议类型不匹配单独报错。连接关闭和 `[DONE]` 本身不代表成功，不补造完成事件，不自动换协议或重发请求。工具说明中的原生协作调用名来自本次实际注册的映射表；有歧义的短工具名不会被猜测执行。
