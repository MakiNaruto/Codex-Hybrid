### 网页端 Codex 接入开关（最小版本）

在现有本地管理页中使用“Codex 接入”开关。开启前展示变更说明，确认后保存路由和模型列表配置；取消不会修改配置。关闭时恢复本次接入前的相关字段（包含字段原先不存在的情况），保留其他配置修改。预览后配置变化、`model_provider` 或 `model_catalog_json` 与接入时不一致、备份校验失败时停止切换，检查配置后刷新重试。关闭时允许清理已修改的 `[model_providers.codex-hybrid]` 表及其子表；重新开启时生成新的 Hybrid provider 表。

如果 Codex 当前直接使用 CC Switch 的第三方厂商，开关同样可用。本工具以 `config.toml` 唯一匹配当前 CC Switch 记录；首次识别时自动加入该记录的全部模型，其他厂商保留在待添加列表。开启后沿用第三方配置，不会额外要求 OpenAI 登录，也不会向 OpenAI 请求模型列表或显示 GPT 系列官方模型。第三方模型可选择 `low`、`medium`、`high` 推理强度。此后记录新增的模型需要手动添加，删除过的自动加入模型也不会重新出现。匹配不到或匹配到多个记录时不会切换，并提示具体错误。
旧会话中的厂商原始模型 ID 唯一匹配时会路由到对应模型。请求的模型未发布且无法唯一匹配时，网关返回 `MODEL_NOT_IN_LIST`。

页面仅显示接入配置是否开启，不检测客户端是否加载配置。切换会备份、迁移本机会话索引；建议先结束任务，确认后可在客户端仍运行时继续。CLI / VS Code 请自行重启；关闭接入后恢复开启前的第三方或原生 provider、原模型选择和接入字段，其他无关配置修改继续保留。管理服务独立保持运行，关闭网页不会撤销接入。关闭接入后，仅当没有活动请求且相关 Codex 进程均未检测到时停止转发；进程仍在运行或检测未知时保留转发，避免中断仍使用旧配置的客户端。若 CC Switch 在开启期间覆盖配置，页面显示“接管已中断”，不会自动抢回。详细范围见[会话迁移](session-migration.md)。

接入区域每秒读取网关未结束请求数，切换确认中也会展示检测快照。计数覆盖经过此网关的官方和第三方请求及流，不包含网页连接测试。检测失败时显示状态未知；计数仅在内存保存。点击“检测”或切换预览时，仅检测 Codex 桌面端、CLI 和 VS Code 是否运行；权限不足或无法确认身份时显示未知。不检测任务忙碌或空闲，不连接任务状态 socket 或内部 IPC。工具执行或等待审批时可能没有网络请求，因此“未检测到活动”不代表可以安全重启。确认后也可能出现新请求。

### 配置与日常操作

首次安装可在向导选择 `3 = 稍后在网页配置`，先进入空管理页。页面顶部是开关置顶的接入状态卡，显示接入状态、可用的第三方模型数量和下一步提示；“已找到凭据”仅表示本地能读取 Key，不代表厂商认证成功。不会自动发送连接测试。

支持按厂商、模型名称或 ID 搜索，并筛选启用状态。模型卡片展示模型信息并提供连接测试。高级参数中可设置厂商请求超时（1–3600 秒）；单次连接测试仍固定使用 60 秒连接超时。

表单修改后标记“未保存”。自动刷新和保存其他厂商会保留这些草稿；手动刷新、切换来源或离开网页前会提醒。草稿只存在当前页面内存，不写浏览器存储。保存会清空 Key 输入框并更新目录。

开启和关闭接入各自保存桌面端操作设置，默认“每次询问”，询问时默认不勾选。开启支持自动启动或重启；关闭仅重启已运行的桌面端，未运行时只恢复配置；也可分别设为“不操作桌面端”。每次仍展示切换确认。自动操作支持 Windows 已安装的 Codex Store 桌面应用，以及 macOS 中通过应用标识验证的 Codex.app，非默认 CODEX_HOME、未识别安装或检测失败时请自行处理，不提供程序路径选择。

### 用量统计

网页与桌面管理页均提供“用量统计”：可选昨天、今天、近 7 天或近 30 天，并按模型筛选。昨天和今天按运行服务所在电脑的本地时区自然日统计，时段为 00:00（含）至次日 00:00（不含），趋势图展示 24 个整点小时桶；今天只计入截至当前已发生的请求。概览显示总 Token、输入、输出及请求数；趋势图可切换 Token 或请求数，近 7 天和近 30 天按 UTC 日期分组，指向或聚焦柱形可查看数值。排行及明细展示各模型用量，缓存命中包含在输入 Token 中。

统计读取本机保留的 `service.jsonl` 及 3 份轮转日志，仅覆盖经过 Hybrid 的请求，不包含网页连接测试或绕过网关的调用，也不代表服务商账单。未返回有效用量的请求只计入请求数，并单独提示；失败请求如已返回用量也会计入。没有日志、读取失败或部分日志不可读时会明确提示。日志轮转可能清理历史，刷新可获取最新已记录用量，不增加聊天内容采集或上传。

### 运行与诊断

Windows 上，每次上游请求都会重新读取当前用户的系统 HTTP/HTTPS 代理及绕过规则。切换代理地址或关闭系统代理不需要重启服务；关闭后走直连，能否访问取决于网络。Windows 不使用进程继承的代理环境变量或 `upstream_proxy` 覆盖系统选择。此设置不控制 Clash TUN 等系统网络层转发，也不解析 PAC 自动配置脚本。macOS 保留原有的显式 `upstream_proxy` 优先、否则通过 Python 读取环境和系统代理的行为。

运行与诊断页显示服务运行时长和最近错误摘要。“最近请求错误摘要”汇总 `service.jsonl`、`service.stderr`、`service.startup.stderr` 及各自保留的 3 份轮转日志，分为上游请求参数错误、请求校验与格式错误、上游服务错误、客户端连接中断、响应失败或未完成、其他运行异常六类。只显示有错误的分类，每条记录均显示错误码，旧记录依据已有 HTTP 状态、连接原因或失败状态显示对应类别码。默认查看最近 24 小时，可选最近 7 天、最近 30 天或全部现有日志，分类内按时间从新到旧排列。新日志记录 Unix 时间及 ISO 8601 UTC 日期时间，页面按本地时区显示。旧日志无时间戳时使用文件修改时间并标注为参考时间。

点击每条记录右侧的“详情”，可查看错误原因、完整请求 ID、模型、处理阶段、日志文件及行号，以及脱敏后的完整已记录日志，并可复制记录。上游流内错误与 HTTP 错误采用相同的分类，包含身份验证、权限、额度、限流、上下文限制和思考强度不支持等原因。例如 GLM 的思考档位错误显示为 `UPSTREAM_REASONING_EFFORT_UNSUPPORTED`。新增上游错误消息最多保留 4096 个字符，超长消息及超过 64 KiB 的异常堆栈会标明截断。历史记录展示当时保存的字段，已清理的记录提示刷新列表。网页和桌面端使用相同的详情入口。

点击“下载诊断”会重新读取状态并下载脱敏 JSON 文件（格式版本 2）。包含程序版本、操作系统类型、架构、Python 版本、服务状态、接入模式、活动计数、错误类别、阶段、时间、HTTP 状态码和耗时。请求错误还可包含匿名请求编号、官方或外部路由类型、接口协议、是否流式、代理是否启用、超时设置、白名单错误码、异常类型和系统错误码，以及项目源码相对文件名和行号。上游错误类型和错误码仅导出白名单内的已知值。匿名编号用于关联同一请求，不包含用户或会话标识；旧日志没有记录的字段无法补齐。

下载的诊断文件使用字段白名单，仅包含脱敏摘要和记录索引。详情中的上游消息、模型、上游地址、原始请求 ID 和异常堆栈保留在本机详情中。API Key、认证头、配置、聊天输入和工具参数等敏感字段会隐藏。文件标注保留日志的覆盖范围和读取状态。升级后重启 Hybrid 服务并刷新页面，后续请求会生成新增错误信息。

正式入口启动后，运行日志 `service.jsonl` 和错误日志 `service.stderr` 按 2 MiB 轮转，各保留 3 份旧文件。异常大的元数据记录会压缩为摘要。后台启动的早期错误写入 `service.startup.stderr`，该文件每次启动重新创建。旧版本尚在运行时需先重启服务才能使用新版日志策略。

### 测试模型连接

独立管理模式下，打开管理页，保存并启用模型，再点击“测试连接”。CC Switch 模式下，可直接在“管理连接”测试来源模型，无需先在“模型管理”添加；测试不会将模型加入客户端列表。测试发送 `Reply with exactly hello and nothing else.`，
输出预算最多 8192 tokens；若模型配置上限更低，则使用更低值。
成功仅表示这次基础请求完成，完整 Codex 会话和工具调用仍需单独验证。

### 在主会话中使用第三方模型

在 Codex 原生模型列表中选择已配置的模型，新建会话并发送：

```text
只回复：Hello World
```

预期回复 `Hello World`。新会话便于确认模型选择；完整会话包含系统提示、工具说明与历史，
输入量通常比管理页连接测试大。

### 跨模型调用子 agent

主会话可选择支持工具调用的官方或第三方模型。网关会向官方、第三方原生 Responses、portable Responses 和 Chat Completions 路径中的协作工具补全已启用的模型目录；父模型可指定官方或其他第三方模型作为子 agent，子 agent 也可在客户端允许的层级与并发限制内继续创建子 agent。原生 Responses 保留工具命名空间和流事件，不转换为 portable 协议。

发送以下最小 prompt。**先替换模型 key**：手动示例是 `deepseek/flash`，向导填写模式是 `custom/default`，CC Switch 以实际注册目录为准，可用 `status` 查看模型 key 列表。验证反向调用时，将主会话切换为第三方模型，并将子模型 key 换成客户端支持的官方模型或另一已启用的第三方模型。

```text
请创建一个原生子 agent，model 使用 deepseek/flash，fork_turns 使用 none，
reasoning_effort 使用该模型支持的 low。
子任务：只回复 CHILD_OK，不调用工具。
请先声明将使用哪个模型创建子 agent，创建后等待完成，再转述结果。
不要用主 agent 自己作答来代替子任务，也不要通过 MCP 或命令行代调用。
```

预期：主 agent 声明模型 → 原生子 agent 活动出现 → 子 agent 回复 `CHILD_OK` → 主 agent 转述。客户端需具备并允许原生子 agent 工具；若当前环境没有该工具，提示词本身不能启用它。

以原生子 agent 活动中的模型信息和网关日志核实实际路由，不能仅凭模型自称使用了某供应商。

### 切换接入与会话迁移

开启或关闭接入时会同步迁移本机会话的 provider 和默认模型。请先完全退出 Codex，在独立浏览器中操作管理页；默认模型可指定，留空取目标列表首项。备份位置、命令行参数和中断恢复见[会话迁移说明](session-migration.md)。

无发生时间的旧日志中，来源、参考时间及脱敏摘要相同的记录合并展示，并标注记录数；带发生时间的新记录分别展示。

Windows 桌面端使用 Restart Manager 请求后台正常退出，不依赖窗口焦点、任务栏点击或模拟快捷键。按进程 ID 和原始创建时间注册目标，核对系统返回的影响范围，只注册桌面主进程，不注册文件、服务或其他客户端，不启用强制结束选项。应用拒绝退出时不重试、不强杀，仍应用接入配置并提示手动重启。

系统后台退出阶段由 Windows 管理；请求成功后最多再等待 12 秒确认主进程退出。配置切换失败时弹出错误，不再启动桌面端。成功后仅尝试启动一次，最多等待 20 秒确认桌面窗口出现；超时提示自行处理，结果按钮为“好的”。窗口出现不代表已验证配置加载，不维护待重启状态。

这是 Windows 的应用会话结束协议，和 Codex 菜单中的退出路径可能不同；不能保证正在执行的任务恢复。弹窗和 `service.jsonl` 会区分身份校验、退出会话创建、资源注册、影响范围校验及后台退出失败。

平台实现边界：管理层通过 `codex_integration.client` 调用安装识别、进程查询、正常退出和启动，Windows 后台退出封装在 `codex_integration.windows_restart_manager`。macOS 后端通过标准安装目录和 Spotlight 查找 Codex.app，验证应用标识和可执行文件；使用 Apple events 请求正常退出，确认进程退出后通过 Launch Services 启动。首次操作可能需要允许自动化控制；权限被拒绝或退出超时时提示手动处理，不强制结束进程。启动结果仅确认桌面主进程已出现。

可在正常交互用户环境中运行 `PYTHONPATH=src python -m codex_integration.probe_windows_restart_manager`（PowerShell 请先设置 `$env:PYTHONPATH='src'`），只创建两个不可见的隔离 GUI 测试程序。实测允许退出的程序在后台收到系统查询及会话结束事件，正常清理后退出；拒绝退出的程序保持运行。探针不操作真实 Codex。已只读确认本机 Codex 注册了系统应用重启能力；真实 Codex 的后台退出和重新启动仍需单独验收。

协议依据：[Restart Manager 应用准则](https://learn.microsoft.com/en-us/windows/win32/rstmgr/guidelines-for-applications)、[RmShutdown](https://learn.microsoft.com/en-us/windows/win32/api/restartmanager/nf-restartmanager-rmshutdown)。

### 独立管理服务与实例互斥

升级后需要重启本地服务，再运行 `manage-url` 获取管理地址。管理监听默认使用转发端口加 1（18891 → 18892；转发端口为 65535 时使用 65534），也可在实例 settings.json 设置不同的 `management_port`。现有模型转发端口和 Codex 配置地址不变。管理端口不接收模型转发请求，原转发端口不再提供管理页面。未开启接入时只运行管理监听；开启前先启动转发监听，端口冲突时保留管理页面并停止本次配置切换。启动或重启 Hybrid 时会恢复已保存的接入选择：接入已开启则自动启动模型转发，接入已关闭则仅启动管理服务。开关表示接入选择，启动或故障不会使其自动关闭；运行状态另行显示。仅刷新或重新打开网页不会停止或重启现有服务。

管理服务监督独立的网关子进程，网关崩溃不影响管理页面。意外退出后依次等待 1、3、10 秒，最多自动重启 3 次；网关连续运行满 60 秒后再次崩溃，重试额度重新计算。达到上限、端口占用或启动失败时停止重试，页面显示异常原因和“重试”入口；需要恢复原配置时关闭接入开关。主动停服不触发重启；401、限流、网络超时等单次请求错误及健康检查超时不触发重启。中断的请求不自动重放，已断开的回答无法续接。管理进程退出后，子进程随私有通信通道关闭而退出；整个管理进程不会自动重启。连接测试使用独立管理上下文，转发未监听时仍可由用户主动测试。已关闭接入但暂保留的转发不会后台自动停服；下次安全关闭操作或重启服务时重新判断。

服务使用 `service.lock` 约束同一数据目录的重复实例；网页、来源同步及 CLI 配置操作共用 `operation.lock`，CLI 启停使用 `control.lock`。不同实例写入同一 Codex 目录的迁移事务还共用该目录的 `.codex-hybrid.lock`。锁由操作系统持有，进程退出或崩溃后自动释放，磁盘文件保留，不要通过删除锁文件解锁。竞争时提示等待后重试；这些锁只约束遵守协议的本工具进程，不能阻止 Codex、CC Switch 或其他编辑器自行修改文件，原有版本及冲突校验继续保留。

任务状态探测已取消，以 Codex 桌面运行检测为目标；进程状态未知不阻止用户确认切换。Windows 运行检测与锁行为仍需实机验收。


### 通知与网关启动故障（2026-10-29）

- macOS 的 CC Switch 目录监听采用 kqueue，接收已打开 SQLite WAL 的写入通知；不会把共享内存文件的读取活动当作配置更新。通知不可用时继续使用定期同步兜底，其他平台保持原生监听。
- 网关启动过程中显示“正在启动”，管理状态查询保持可用。接入切换在启动后重新校验配置和会话索引版本，等待期间发生外部修改则停止提交。
- 网关就绪等待上限为 10 秒；CLI 控制请求最多等待 15 秒，为失败后的子进程清理留出时间。单次状态查询不会等待网关启动完成。
- 启动失败会按固定类别提示端口占用、权限不足、启动超时、配置无效、就绪前退出或其他启动异常；诊断导出只保留这些类别，不导出原始异常消息。


### 桌面切换与日志积压处理（2026-10-29）

等待 Codex 桌面端退出或启动时，管理页仍可查询状态，并显示准备切换、正常退出、应用配置或启动桌面端的进度。切换进行期间，其他页面不能重复或反向提交切换。配置锁不覆盖桌面系统调用；提交前重新检查配置，并重新规划退出时刷新的会话索引。发现配置变化时停止写入，不继续启动桌面端。

网关请求线程通过后台线程发送日志，管理进程也通过后台线程写入日志；桌面操作结果复用管理进程的日志队列，切换返回不等待落盘。两个队列各最多等待 256 条记录，每条在入队前限制为 16 KiB 元数据摘要。队列满时丢弃新日志，事件日志的实际写入及轮转失败也计入已知丢弃数量；网关状态和诊断中的 `forwarding.log_dropped_records` 累计展示本次管理服务运行期间两侧已知的丢弃数量，网关重启不清零。日志积压和磁盘卡顿不阻塞进程监督、自动重启或请求线程；每轮监督最多读取 64 条日志，避免持续流量挤占监督。退出时日志最多等待 0.2 秒排空，未写出的尾部日志可能丢失，进程崩溃时的在途日志也无法保证保留。

数据库备份长期被独占时，单次备份最多等待约 5 秒后停止本次切换，并提示关闭占用程序后重新预览。日志文件清理交给后台线程；`RuntimeLog.close()` 总等待上限为 0.2 秒，Python 自动日志清理也不会等待卡住的写入锁。正常情况下会保留 stderr 末尾未换行的内容；异常阻塞时仍可能丢失尾部日志。

## 管理已添加模型

主页面只显示已添加的第三方模型。点击“添加模型”搜索并批量选择；点击“查看详情”设置当前模型的兼容模式、测试连接或移除模型。新 Responses 配置默认开启 Portable，显式关闭可保留原生格式；Chat 使用其现有转换。移除不会删除厂商或 CC Switch 配置，但会阻止后续路由；已开始的请求使用自己的配置快照。添加、移除后重启客户端以刷新其模型列表。

“管理连接”中维护独立厂商，或只读复用 CC Switch。已停用的来源模型需先在来源中恢复。当前 Codex 第三方记录第一次被识别时会自动启用该记录的全部模型；此后仅发现新模型不会自动启用，删除过的模型也可逐个移除且不会复活。不同记录保持独立，即使厂商名和模型名相同。模型级设置保存在 Hybrid，不会改写 CC Switch。
