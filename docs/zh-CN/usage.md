### 网页端 Codex 接入开关（最小版本）

在现有本地管理页中使用“Codex 接入”开关。开启前展示变更说明，确认后保存路由和模型列表配置；取消不会修改配置。关闭时恢复本次接入前的相关字段（包含字段原先不存在的情况），保留其他配置修改。预览后配置变化、接入字段被外部修改或备份校验失败时停止切换，检查配置后刷新重试。

页面仅显示接入配置是否开启，不检测客户端是否加载配置。切换会备份、迁移本机会话索引；建议先结束任务，确认后可在客户端仍运行时继续。CLI / VS Code 请自行重启；关闭接入后选择官方模型。管理服务独立保持运行，关闭网页不会撤销接入。关闭接入后，仅当没有活动请求且相关 Codex 进程均未检测到时停止转发；进程仍在运行或检测未知时保留转发，避免中断仍使用旧配置的客户端。详细范围见[会话迁移](session-migration.md)。

接入区域每秒读取网关未结束请求数，切换确认中也会展示检测快照。计数覆盖经过此网关的官方和第三方请求及流，不包含网页连接测试。检测失败时显示状态未知；计数仅在内存保存。点击“检测状态”或切换预览时，仅检测 Codex 桌面端、CLI 和 VS Code 是否运行；权限不足或无法确认身份时显示未知。不检测任务忙碌或空闲，不连接任务状态 socket 或内部 IPC。工具执行或等待审批时可能没有网络请求，因此“未检测到活动”不代表可以安全重启。确认后也可能出现新请求。

### 配置与日常操作

首次安装可在向导选择 `3 = 稍后在网页配置`，先进入空管理页。页面顶部按“配置模型 → Codex 接入 → 重启并验证”展示准备情况；“已找到凭据”仅表示本地能读取 Key，不代表厂商认证成功。不会自动发送连接测试。

支持按厂商、模型名称或 ID 搜索，并筛选启用状态。模型卡片展示模型信息并提供连接测试。高级参数中可设置厂商请求超时（1–3600 秒）；单次连接测试仍固定使用 60 秒连接超时。

表单修改后标记“未保存”。自动刷新和保存其他厂商会保留这些草稿；手动刷新、切换来源或离开网页前会提醒。草稿只存在当前页面内存，不写浏览器存储。保存会清空 Key 输入框并更新目录。

开启和关闭接入各自保存桌面端操作设置，默认“每次询问”，询问时默认不勾选。开启支持自动启动或重启；关闭仅重启已运行的桌面端，未运行时只恢复配置；也可分别设为“不操作桌面端”。每次仍展示切换确认。自动操作支持 Windows 已安装的 Codex Store 桌面应用，以及 macOS 中通过应用标识验证的 Codex.app，非默认 CODEX_HOME、未识别安装或检测失败时请自行处理，不提供程序路径选择。

### 运行与诊断

管理页自动读取一次运行状态，也可在底部点击“刷新状态”，查看服务运行时长和最近错误摘要。“最近请求错误摘要”汇总 `service.jsonl`、`service.stderr`、`service.startup.stderr` 及各自保留的 3 份轮转日志，分为请求校验与格式错误、上游服务错误、客户端连接中断、响应失败或未完成、其他运行异常五类；只显示有错误的分类，各分类的问号按钮提供说明。默认查看最近 24 小时，可选最近 7 天、最近 30 天或全部现有日志。按记录时间筛选，并在分类内按时间从新到旧排列；扫描所有现有日志，不再限制为文件尾部 128 KiB。已轮转清理的历史无法恢复，页面会提示记录可能不完整。服务及启动异常归入其他类，只展示安全的异常类型和系统错误码（例如 WinError 10053），不展示原始异常消息、堆栈或路径；新日志采用 JSON Lines 格式，统一记录 Unix 时间及 ISO 8601 UTC 日期时间；页面按本地时区显示完整日期、时间和时区。旧日志无时间戳时使用文件修改时间并明确标注，不能还原实际发生时间。

点击“下载脱敏诊断”会重新读取状态并下载 JSON 文件。只包含服务状态、接入模式、活动计数、错误类别、阶段、时间、HTTP 状态码和耗时；不包含原始配置、完整日志、Key、认证头、聊天文本或工具参数，不自动上传。读取失败时显示错误；没有错误摘要也不代表完整日志中没有错误。

正式入口启动后，运行日志 `service.jsonl` 和错误日志 `service.stderr` 按 2 MiB 轮转，各保留 3 份旧文件。异常大的元数据记录会压缩为摘要。后台启动的早期错误写入 `service.startup.stderr`，该文件每次启动重新创建。旧版本尚在运行时需先重启服务才能使用新版日志策略。

### 测试模型连接

打开管理页，保存并启用模型，再点击“测试连接”。测试发送 `Reply with exactly hello and nothing else.`，
输出预算最多 8192 tokens；若模型配置上限更低，则使用更低值。
成功仅表示这次基础请求完成，完整 Codex 会话和工具调用仍需单独验证。

### 在主会话中使用第三方模型

在 Codex 原生模型列表中选择已配置的模型，新建会话并发送：

```text
只回复：Hello World
```

预期回复 `Hello World`。新会话便于确认模型选择；完整会话包含系统提示、工具说明与历史，
输入量通常比管理页连接测试大。

### 让官方主 agent 调用第三方子 agent

主会话选择支持原生子 agent 的官方模型，发送以下最小 prompt。**先替换模型 key**：手动示例是 `deepseek/flash`，向导填写模式是 `custom/default`，CC Switch 以实际注册目录为准，可用 `status` 查看模型 key 列表。

```text
请创建一个原生子 agent，model 使用 deepseek/flash，fork_turns 使用 none，
reasoning_effort 使用该模型支持的 low。
子任务：只回复 CHILD_OK，不调用工具。
请先声明将使用哪个模型创建子 agent，创建后等待完成，再转述结果。
不要用主 agent 自己作答来代替子任务，也不要通过 MCP 或命令行代调用。
```

预期：主 agent 声明模型 → 原生子 agent 活动出现 → 子 agent 回复 `CHILD_OK` → 主 agent 转述。客户端需具备并允许原生子 agent 工具；若当前环境没有该工具，提示词本身不能启用它。

以原生子 agent 活动中的模型信息和网关日志核实实际路由，不能仅凭模型自称使用了某供应商。

服务启停与状态查询见 [常用命令](../../README.zh-CN.md#常用命令)。后续命令使用统一用户目录，自定义目录需持续显式指定；

### 切换接入与会话迁移

开启或关闭接入时会同步迁移本机会话的 provider 和默认模型。请先完全退出 Codex，在独立浏览器中操作管理页；默认模型可指定，留空取目标列表首项。备份位置、命令行参数和中断恢复见[会话迁移说明](session-migration.md)。

无发生时间的旧日志中，来源、参考时间及脱敏摘要相同的记录合并展示，并标注记录数；带发生时间的新记录分别展示。

Windows 桌面端使用 Restart Manager 请求后台正常退出，不依赖窗口焦点、任务栏点击或模拟快捷键。按进程 ID 和原始创建时间注册目标，核对系统返回的影响范围，只注册桌面主进程，不注册文件、服务或其他客户端，不启用强制结束选项。应用拒绝退出时不重试、不强杀，仍应用接入配置并提示手动重启。

系统后台退出阶段由 Windows 管理；请求成功后最多再等待 12 秒确认主进程退出。配置切换失败时弹出错误，不再启动桌面端。成功后仅尝试启动一次，最多等待 20 秒确认桌面窗口出现；超时提示自行处理，结果按钮为“好的”。窗口出现不代表已验证配置加载，不维护待重启状态。

这是 Windows 的应用会话结束协议，和 Codex 菜单中的退出路径可能不同；不能保证正在执行的任务恢复。弹窗和 `service.jsonl` 会区分身份校验、退出会话创建、资源注册、影响范围校验及后台退出失败。

平台实现边界：管理层通过 `desktop.client` 调用安装识别、进程查询、正常退出和启动，Windows 后台退出封装在 `desktop.windows_restart_manager`。macOS 后端通过标准安装目录和 Spotlight 查找 Codex.app，验证应用标识和可执行文件；使用 Apple events 请求正常退出，确认进程退出后通过 Launch Services 启动。首次操作可能需要允许自动化控制；权限被拒绝或退出超时时提示手动处理，不强制结束进程。启动结果仅确认桌面主进程已出现。

可在正常交互用户环境中运行 `PYTHONPATH=src python -m desktop.probe_windows_restart_manager`（PowerShell 请先设置 `$env:PYTHONPATH='src'`），只创建两个不可见的隔离 GUI 测试程序。实测允许退出的程序在后台收到系统查询及会话结束事件，正常清理后退出；拒绝退出的程序保持运行。探针不操作真实 Codex。已只读确认本机 Codex 注册了系统应用重启能力；真实 Codex 的后台退出和重新启动仍需单独验收。

协议依据：[Restart Manager 应用准则](https://learn.microsoft.com/en-us/windows/win32/rstmgr/guidelines-for-applications)、[RmShutdown](https://learn.microsoft.com/en-us/windows/win32/api/restartmanager/nf-restartmanager-rmshutdown)。

### 独立管理服务与实例互斥

升级后需要重启本地服务，再运行 `manage-url` 获取管理地址。管理监听默认使用转发端口加 1（18891 → 18892；转发端口为 65535 时使用 65534），也可在实例 settings.json 设置不同的 `management_port`。现有模型转发端口和 Codex 配置地址不变。管理端口不接收模型转发请求，原转发端口不再提供管理页面。未开启接入时只运行管理监听；开启前先启动转发监听，端口冲突时保留管理页面并停止本次配置切换。启动时若接入配置已开启，则恢复转发监听；失败会显示故障和“恢复模型转发”入口。

管理页面和转发目前仍在同一 Python 进程，监听和运行控制已拆分；尚不提供进程崩溃隔离、监督或自动重启。连接测试使用独立管理上下文，转发未监听时仍可由用户主动测试。已关闭接入但暂保留的转发不会后台自动停服；下次安全关闭操作或重启服务时重新判断。

服务使用 `service.lock` 约束同一数据目录的重复实例；网页、来源同步及 CLI 配置操作共用 `operation.lock`，CLI 启停使用 `control.lock`。不同实例写入同一 Codex 目录的迁移事务还共用该目录的 `.codex-hybrid.lock`。锁由操作系统持有，进程退出或崩溃后自动释放，磁盘文件保留，不要通过删除锁文件解锁。竞争时提示等待后重试；这些锁只约束遵守协议的本工具进程，不能阻止 Codex、CC Switch 或其他编辑器自行修改文件，原有版本及冲突校验继续保留。

任务状态探测已取消，以 Codex 桌面运行检测为目标；进程状态未知不阻止用户确认切换。Windows 运行检测与锁行为仍需实机验收。
