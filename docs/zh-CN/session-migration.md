# 切换路由时迁移会话

开启 Codex Hybrid 接入、关闭接入，以及命令行 `activate`、`rollback`、`uninstall`，会同步迁移所选 Codex 数据目录中的全部本机会话记录，包括第三方 provider 的旧会话、归档、子会话和分页历史片段。云端会话不在迁移范围内。

迁移同步更新数据库的 provider / model、会话文件头的 provider，以及历史轮次的模型字段。用户消息、模型回复和工具调用内容保留原始字节；分页历史的引用偏移随元数据长度变化同步修正。数据库中已缺失历史文件的条目只更新索引，预览会单独报告数量，不会生成或补造历史。

支持普通 `.jsonl` 和 Codex 自动压缩的 `.jsonl.zst` 历史。压缩历史参与来源查找与迁移，分页引用按解压后的字节长度修正；迁移后仍保存为压缩文件。备份保留原始压缩文件，失败回滚与中断恢复可还原原始字节。Python 3.14+ 使用内置 Zstandard，较早版本由启动脚本自动安装 `zstandard` 依赖。

## 操作方式

1. 在独立浏览器打开管理页。开启和关闭接入都建议先结束任务并退出 Codex，但可在确认影响后继续，进程检测仅作提示。
2. 切换接入开关，核对会话迁移信息后确认。默认模型根据实例预设或目标模型列表自动选择。
3. 迁移完成后重新打开 Codex。

网页开启和关闭接入时，进程检测结果仅更新管理页“Codex 接入”区域，不在确认框重复提示，也不作为禁止切换的条件。点击“检测状态”同步更新桌面端、VS Code 端、CLI 端和网关状态；网关活动状态展示在 CLI 端后方，仅统计网关请求，不自动轮询。确认框的影响详情说明请求、工具调用和未保存状态可能受影响；确认后继续备份并切换到目标路由，网关保持运行，之后需手动重启 Codex。检测到进程不代表任务忙碌，无法读取进程信息会显示未知；辅助进程、更新器和僵尸进程不作为运行实例。

CLI 迁移和中断备份恢复仍要求先退出 Codex。不要同时使用 CC Switch 等工具修改配置或会话；预览后数据发生变化、备份异常等仍会停止写入。这些数据校验不会因确认活动影响而跳过。

### Windows

Windows 与 macOS 共用会话迁移逻辑。默认 Codex 数据目录为 `$env:USERPROFILE\.codex`；设置了 `CODEX_HOME` 或实例保存了自定义配置路径时，以所选目录为准。会话文件按字节读取和写入，保留原有 LF / CRLF 换行，并按实际字节长度修正历史引用偏移。配置文件使用 UTF-8，路径支持中文和空格。

在项目根目录的 PowerShell 中关闭接入并迁移会话：

```powershell
.\scripts\codex-hybrid.cmd rollback --default-model gpt-6.1-sol
```

网页开关无需替换命令。建议先退出 Codex 桌面端、使用同一数据目录的 VS Code 插件和 CLI，再在独立浏览器中切换。Windows 下文件占用或 SQLite 写锁仍可能阻止迁移；确认活动影响不会解除操作系统的文件锁。

### 网页切换时的迁移警告

网页开启或关闭接入时，如果会话迁移预检发现历史来源缺失、历史格式或偏移无效、引用循环、ID 冲突、数据库结构不兼容或路径不安全，会警告并跳过本次全部旧会话迁移，继续保存接入配置。历史片段之间存在字节偏移依赖，因此不会只修改其中一部分；旧会话文件和数据库保持原样，仍保留原线路和模型。新会话使用切换后的配置。

警告同时显示在确认框和切换结果中。确认切换时写入实例数据目录的 `session-migration-warnings.jsonl`，日志按 2 MiB 轮转并最多保留 3 份旧文件，包含时间、错误码、目标线路；历史来源缺失时还包含会话路径和来源 ID，不记录消息内容。取消预览不会写入日志。备份清单也保存本次警告，日志写入失败会在结果中提示。

该降级仅处理上述预检错误。配置校验、模型选择、预览后数据变化、备份失败、实际写入失败以及中断恢复要求仍会阻止切换。CLI 保持严格迁移行为。

命令行也支持指定模型：

```bash
codex-hybrid activate --default-model gpt-6.1-sol
codex-hybrid rollback --default-model gpt-6.1-sol
codex-hybrid uninstall --default-model gpt-6.1-sol
```

不指定时，按目标模型列表的顺序选择第一个可见模型。切回 `openai` 时只从官方模型中选择；当前列表首项为 `gpt-6.1-sol`，代码不固定其名称。指定的模型不在目标列表或目标列表为空时会停止操作。

可在实例的 `settings.json` 中预设每条线路的会话默认模型；单次命令指定的模型优先级更高：

```json
{
  "session_default_models": {
    "openai": "gpt-6.1-sol",
    "codex-hybrid": "gpt-6-astra"
  }
}
```

将该字段合并进已有设置，不要替换其他设置。手动编辑实例设置后重启网关。没有会话时，若模型列表已准备好，也会更新配置的默认模型，供新会话使用。

## 备份与中断恢复

每次操作前会在实例数据目录的 `session-migrations/<备份ID>/` 保存数据库快照、发生变化的会话及配置文件，并记录迁移清单。该目录含完整对话和配置，应按私人数据保存。迁移没有自动删除备份。

普通写入失败会恢复已写文件并回滚数据库。进程被强制终止时，清单可能停留在 `applying`，后续切换会停止，避免覆盖未完成的恢复现场。保持 Codex 关闭，运行：

```bash
codex-hybrid recover-sessions --backup /绝对路径/实例数据目录/session-migrations/备份ID
```

自定义实例同时传入 `--data-dir /绝对路径/实例数据目录`。此命令仅恢复中断的迁移；已完成的迁移不能用它覆盖后续产生的新对话。若中断后会话又发生变化，恢复也会停止，请保留整个备份目录排查。

Windows PowerShell 示例（路径替换为切换结果中返回的实际备份目录）：

```powershell
.\scripts\codex-hybrid.cmd recover-sessions --backup "D:\Codex Data\session-migrations\备份ID" --data-dir "D:\Codex Data"
```

切回 OpenAI 只处理会话的线路和模型选择，不保证第三方模型产生的所有历史内容均能被官方后端接受。恢复对话成功与实际模型回复成功是两层验证。
