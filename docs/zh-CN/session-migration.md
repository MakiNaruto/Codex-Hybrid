# 切换路由时迁移会话索引

开启 Codex Hybrid 接入、关闭接入，以及命令行 `activate`、`rollback`、`uninstall`，只迁移所选 Codex 数据目录中的本机会话索引。归档、子会话和分页会话均在范围内；云端会话及其他数据目录的会话不参与。

| 操作 | 会话索引中的线路 | 会话索引中的模型 |
| --- | --- | --- |
| 开启接入 | 改为 `codex-hybrid` | 保留原模型 |
| 关闭接入，当前模型属于官方列表 | 改为 `openai` | 保留原模型 |
| 关闭接入，当前模型属于第三方 | 改为 `openai` | 使用官方列表首个可用模型 |

官方模型身份按实例的 `official_models` 名单判断，不按名称前缀或当前 provider 判断；回退模型按模型目录顺序过滤官方名单和隐藏项后选择。已经属于官方名单的模型即使暂时不可用也保留，由 Codex 自身处理。索引中没有记录模型时也保持未设置，由 Codex 使用自己的恢复规则。官方名单不可用，或需要回退却找不到可用官方模型时，操作会停止。

开启后原模型已不在混合列表时仍保留，由 Codex 自身处理。关闭时被替换的第三方模型不会在再次开启时自动恢复。

迁移不修改 `.jsonl` / `.jsonl.zst` 历史文件、文件头、历史轮次模型、历史引用偏移或分页缓存。接入配置仍会更新路由字段，但不选择、插入或覆盖配置文件的 `model`。CLI 使用旧配置快照切换时也保留当前根级模型设置或未设置状态。`--default-model` 不再支持，旧的 `session_default_models` 预设不再用于迁移；模型连接配置中的同名默认项不受影响。

## 操作方式

1. 在独立浏览器打开管理页。建议先结束任务并退出 Codex；网页仍允许确认后继续，进程检测仅作提示。
2. 切换接入开关。预览显示会话索引数量、待补齐索引数量和缺少历史文件的已有索引数量。取消预览不写入数据。
3. 确认后完成索引迁移，再重新打开需要使用新路由的 Codex。

网页确认框保留重启说明，影响详情不显示默认模型或重复线路说明。点击“检测状态”更新桌面端、VS Code 端、CLI 端和网关状态；网关活动仅统计网关请求。切换后管理服务继续运行；转发在无活动请求且未检测到相关进程时才停止。可选操作本机桌面端，其他客户端自行重启。CLI 迁移和中断恢复仍要求先退出 Codex。

### 缺失索引由 Codex 补齐

预览只扫描本地文件名、必要的会话头和已有索引，不启动 Codex 或重建索引。多个历史片段按逻辑会话计数，不按文件份数计数。

确认后，只有缺少索引时才启动一个独立 Codex app-server，通过 `thread/read` 补齐这些会话的元数据。不会调用 `thread/resume` 或 `turn/start`，不会发起模型生成。辅助进程使用临时认证存储，阻止 HTTP 联网，不修改用户配置；退出后才开始索引迁移事务。

程序自动寻找 PATH、常见桌面安装目录及运行中的 Codex 可执行文件。自定义安装位置可在实例 `settings.json` 增加 `codex_executable`（可执行文件的完整路径），然后重启网关。找不到程序、协议不兼容或索引补齐不完整时，会停止切换。已有完整索引时无需启动辅助进程。

Codex 补索引本身可能创建或更新它的元数据库。补齐后重新校验原有索引、文件清单和预览状态，确认无冲突，再生成迁移备份。补齐失败时不会应用路由更改，但 Codex 已建立的索引会保留。

历史文件缺失但索引仍存在的会话只更新索引，不补造历史。历史文件中的来源缺失、引用循环或旧偏移不再阻止索引迁移，因为本程序不重写这些文件；历史本身是否能够恢复仍由 Codex 判断。

### Windows

Windows 与 macOS 共用相同逻辑。默认数据目录为 PowerShell 的 `$env:USERPROFILE\.codex`，设置 `CODEX_HOME` 或使用自定义实例时以所选目录为准。路径支持中文和空格，配置按 UTF-8 读取。

在项目根目录执行：

```powershell
.\scripts\codex-hybrid.cmd rollback
```

不要同时使用 CC Switch 等工具修改配置和索引。Windows 文件占用或 SQLite 写锁、预览后数据变化、备份或写入失败仍会阻止切换。

### 网页切换时的迁移警告

数据库结构不兼容、路径不安全、会话 ID 冲突或无法识别无索引会话元数据时，网页会警告并跳过全部索引迁移，继续保存接入配置。CLI 保持严格行为。

警告显示在确认框和结果中，确认时写入实例目录的 `session-migration-warnings.jsonl`，按 2 MiB 轮转并最多保留 3 份旧文件，不记录消息内容。取消预览不会写日志。配置校验、官方模型列表校验、索引补齐失败、预览失效、备份和实际写入失败不会降级跳过。

## 备份与中断恢复

第一次实际修改前（包括 Codex 补索引之前），在实例数据目录的 `session-baselines/<数据目录ID>/` 保存一份固定基线：索引数据库、将修改的配置文件，以及当次兼容修复涉及的历史文件。不会复制全部聊天正文。每个 Codex 数据目录独立保存，不覆盖、不自动清理。旁边的 `<数据目录ID>.json` 保存完整性校验；基线缺失或损坏会停止切换。

确认需要放弃旧基线、以当前状态重新建立时，先退出相关 Codex 客户端，再运行 `codex-hybrid reset-session-baseline --codex-home /Codex数据目录 --data-dir /实例目录`。此命令重置基线，下一次实际修改前重新备份；它不执行历史回退。基线是人工排障材料，不应覆盖恢复到已有新会话的数据库。

每次迁移仍在 `session-migrations/<备份ID>/` 临时保存完整索引快照、被修改文件和恢复清单。成功或确认完整回滚后立即删除；清理失败不使已成功的切换失败，启动及下次切换时重试。中断或回滚未完成的记录保留并阻止继续切换。备份可能包含私人索引、配置和被修复的历史内容。

普通写入失败会恢复路由配置并回滚索引更新。进程中断后若清单停留在 `applying`，后续切换会停止。保持 Codex 关闭后运行：

```powershell
.\scripts\codex-hybrid.cmd recover-sessions --backup "D:\Codex Data\session-migrations\备份ID" --data-dir "D:\Codex Data"
```

macOS 或已安装 CLI 可运行 `codex-hybrid recover-sessions --backup /绝对路径/备份目录`；自定义实例同时传入 `--data-dir`。

恢复仅支持中断的迁移，不覆盖已完成迁移后产生的新数据。旧版本包含历史文件的中断备份仍可恢复；新版本只恢复所拥有的索引线路、模型字段和路由配置，不改标题等无关元数据。

切回 OpenAI 不保证第三方模型产生的全部历史内容都能被官方后端接受。模型选择正确、历史可恢复和真实后端能够回复是不同层面的验证。

每次 SQLite 数据库备份设置 5 秒锁等待与复制截止时间，分批复制并检查单调时钟；数据库长期被独占时返回 `SESSION_BACKUP_TIMEOUT`，不继续提交接入配置和索引迁移。关闭占用数据库的程序后重新预览、重试；首次基线超时时不会发布为可信基线，未完成的准备目录在重试时清理。事务备份超时会清理本次临时记录；此前已由 Codex 补齐的索引仍按既有规则保留。该截止时间不保证中断底层操作系统中已经卡住的文件 I/O。
